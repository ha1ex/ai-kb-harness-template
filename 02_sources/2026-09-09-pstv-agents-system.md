# Саммари: «Агенты PartyStation: как устроена система»

> Слой `02_sources`: короткое саммари одного raw-артефакта. Оригинал — текстовый дамп страницы
> (команда PartyStation, публикация на Birta; прочитано 2026-09-09). Номера разделов — по оригиналу.

Ключевые утверждения источника:

- §1–2. Система из 19 агентов-сотрудников (11 в работе) для маркетинга и контент-студии квиз-игр. Принцип: «агент предлагает, код проверяет, человек одобряет, потом исполняется». «Системная валидация не равна одобрению человека» записано как абсолютное правило.
- §3. Агент — папка из четырёх файлов: `config.yaml` (контракт: кто, когда, что можно самому, кто проверяет, что знает, замороженная метрика), `prompt.md` (инструкция из пяти блоков), `tools.py` (базовые инструменты из общей фабрики, личность в замыкании), `knowledge/` с `how_it_works.md`, который обновляется в том же коммите, что код. «Новый агент создаётся копированием шаблона, никогда копированием соседа».
- §3. Уровни автономии 1/2/3 и два списка «само» / «только через человека»; пороги живут в контракте, не в коде. Одна «замороженная» метрика на роль с минимальной выборкой: CRM — выручка на сообщение при n ≥ 200; сценарист — 80% принятых с первого раза; критик — 90% точности флагов; библиотекарь — 80% закрытых проблем.
- §3. Виртуальные эксперты — «самопроверка той же модели, дисциплина промпта, а не независимый контроль»; их вердикт добавляет 0,15 к уверенности.
- §4. Цикл Gather → Think → Decide → Execute → Learn; входящие задачи первыми; чекпоинт каждой фазы; критик с чистым контекстом после каждого прогона; рефлексия по последним пяти поправкам куратора; Learn вынесен в отдельную ночную работу.
- §5. Три слоя гардрейлов: детерминированный код (пять вердиктов; уверенность 0,8 для необратимого и 0,3 для обратимого; «по умолчанию — к человеку»; 31 золотой принцип запрещает автоодобрение), вторая модель с чистым контекстом или «тупая стена» («рецензент недоступен — блок»; находки LLM-судей в конвейере квизов — только совет), человек.
- §6. Одобрение — контракт, а не интерфейс: одна запись, несколько поверхностей (веб, Telegram, CLI). Подпись эффекта: SHA-256 канонизированного содержимого считается при показе и пересчитывается в момент действия; несовпадение — отказ. Атомы знаний активируются пакетом с отпечатком и сроком 48 часов; правка после одобрения снимает утверждение. Честное ограничение: подпись не криптографическая, «до фикса автономия не расширяется».
- §7. Инвариант «построено, но не подключено»: нельзя ставить задачу выключенному агенту; достижимость включённых проверяется на ревью.
- §8. Две роли моделей вместо имён (стандартная и премиальная), имя модели только в одном файле политики; семафор на три слота; Codex как запасной движок с пометкой деградации; 28 архитектурных инвариантов с храповиком («существующие нарушения заморожены, новые красят проверку, список может только уменьшаться»); replay-гейт: семь дней предложений прогоняются через новую версию промпта.
- §9–10. 6 512 коммитов за 184 дня, треть — авто-синк знаний; 510 письменных планов до кода, вторая модель читает план; знания обновляются в том же коммите; papercuts — 172 записи, только добавление, дедуп по хешу, «не бэклог»; инцидент закрывается фиксом, тестом-стражем и строкой каталога, урок записывается до фикса; реестр дефектов: «пункт закрыт, только если без фикса гейт краснеет».
- §11. Уроки: «ноль исполненных предложений за шесть недель — провал интерфейса» (одобрения переехали в Telegram); «цена кодовой базы — контекст, а не диск» (496 КБ навыков ужаты до 38 КБ); «пустой результат под зелёным статусом — тихий провал»; «деградация обязана быть громкой»; «тесты не имеют права трогать живые каналы»; гейт свежести проверяет личность базы, а не правдоподобие числа.
- §12. Что не работает: одобрение не криптографическое; неполная изоляция процессов; «построено, но не подключено» (выключенные рекламные агенты, самокодирующий модуль без вызовов); фазе Learn у CRM нечему учиться 123 дня — показывается как «недостаточно данных».
- §14. Чек-лист «одного сотрудника с нуля»: папка, не промпт; одна замороженная метрика; правила в коде; подписывай эффект; второй взгляд с закрытием при отказе; одобрение там, где человек живёт; знания с метаданными (кому, срок, статус, источник); тишина не успех; урок до фикса; движок на подписке.

Границы источника: единичный опыт одной команды; пороги и проценты — настройки их контрактов, не переносимые константы; измеренных эффектов большинства практик в статье нет, кроме описанных инцидентов.
