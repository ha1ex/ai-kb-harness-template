# Human viewer

Run `pnpm --dir tools/viewer dev` from the repository root, then open http://localhost:5173. Build with `pnpm --dir tools/viewer build`; preview with `pnpm --dir tools/viewer preview`. `pnpm --dir tools/viewer test` checks catalog behavior in temporary projects.

Project identity can be set in `00_context/project.json` as `{name, description, status}`. Explicit viewer values override this identity. The viewer reads `kb.config.mjs` → `viewer: {name, description, status, accent}` and `layers.indexable`. Raw Markdown is excluded unless `01_raw` is listed in the configured layers or `viewer.includeRaw: true` is set. Links to unpublished sources may therefore be unavailable. `REPO_ROOT` (or `KB_ROOT` for builds) selects a different project. Reading, the palette and static text search need no model or search index; development semantic search requires its existing index. Development search retains the hybrid/vector/BM25 API. Static publication uses local substring matching and hides unsupported search mode controls.

Topics come from `00_context/spaces.json`: `{ "spaces": [{ "id": "research", "title": "Research", "description": "…", "start_docs": ["03_wiki/finding.md"] }] }`. IDs use letters, numbers, underscores and hyphens. Frontmatter `audience: [research]` adds documents to topics. Missing optional topic configuration is supported; untagged documents stay in library and search. The supplied topics reference the neutral walkthrough and can be replaced or removed after initialization.

Build output in `dist/` contains the entire selected Markdown corpus and parsed metadata in `data/catalog.json`. Review this corpus before publishing. No private dot-directories or symlinked documents are included. Deploy at the origin root on any static host supporting directory index files. Generated `/doc/path.md/index.html` files support direct requests, including hosts which redirect to a trailing slash; `/space/:id`, `/library`, and legacy routes are also generated. No proprietary deployment configuration is required.

Development retains existing `/api/*` endpoints and adds `/api/viewer` for the shared catalog. Optional graph/SkillOpt surfaces need their existing development data and are not generated as interactive static tools. Documents, navigation, source links, palette and library work offline after assets/data load.

Document layout uses the existing MPLC-derived KB components, theme tokens and navigation principles. Explicit `id` attributes make accordion items and native `details` blocks deep-linkable. Plain heading IDs use GitHub-style slugs. Relative and root Markdown links open viewer routes. Images currently show alt-text placeholders; arbitrary binary attachments and Mermaid execution are outside this release.
