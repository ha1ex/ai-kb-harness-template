# Общие улучшения витрины из MPLC

## Главное

Выпуск 0.8.0 переносит проверенные способы работы MPLC в переиспользуемый шаблон. Частные данные, фирменные названия и зеркала чужих методологий остаются в исходном проекте.

## Результат для читателя

- Каталог `/documents` группирует действующие материалы, части комплекта и прежние версии. Поиск и категория сохраняются в URL.
- Markdown скачивается из открытого документа. Каждый документ можно напечатать в PDF через браузер; заранее собранная версия получает отдельную кнопку PDF.
- Команда сборки создаёт автономный HTML A4 и PDF с паспортом исходного текста. Проверка обнаруживает устаревший экспорт.
- Раздел `/methods` показывает карточки методологий, их назначение, первоисточник и лицензию. Это справочные материалы; они не подтверждают утверждения о проекте.
- Канвас `/maps` и `/maps/:id` показывает нейтральные схемы: поиск, перемещение, масштаб, выбор блока и связей, источники и табличная версия. Добавлен по уточнению владельца: нужны и канвас, и каноны.
- Каноны доступны по закреплённым ссылкам с указанием условий; авторские карточки объясняют маршрут чтения.
- Боковое меню показывает общие разделы. Документ имеет один основной путь: часть — через главный документ, результат — через тему, остальные — через каталог или библиотеку.

## Ограничения

Настройки читаются из `KB_ROOT` и `kb.config.mjs`. Произвольные индексируемые слои сохраняются. Отсутствие новых реестров даёт пустое состояние. Публикуются только явно заявленные HTML/PDF и уже доступные Markdown. Скрытые пути, ссылки наружу через файловую систему и сырые материалы по умолчанию не публикуются. HTML открывается в изолированном iframe; внешние ссылки могут открывать новую вкладку.

Конкретные категории, примеры и методологии выбирает проект. Шаблон не получает решения MPLC, личные данные, скопированные сторонние каноны или разрешение всем будущим проектам автоматически публиковать изменения.

## Решения исполнителя

Сохраняем React/Vite и существующую систему ролей, ревью и подписей. Не заменяем её устройством MPLC. Используем общий парсер Markdown витрины при печати. PDF строится headless Chromium; без него HTML сохраняется, а команда сообщает недостающую зависимость. Не вводим минимальное число страниц.

## Приёмка

Нейтральный пример позволяет открыть комплект, архив, Markdown, печать и PDF. Проверки покрывают нестандартные слои, отсутствующие файлы, конфликт ID, недопустимые связи, скрытые пути, символические ссылки и устаревший экспорт. Пройдены общие тесты, тесты витрины, статическая сборка и проверка выпуска. Документация описывает настройку, обновление существующего проекта и действия человека после публикации.
