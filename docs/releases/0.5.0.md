# Выпуск 0.5.0 — рабочая система проекта

## Главное

9 сентября 2026 года. Пять ролей, четыре сценария и профиль проекта связывают контекст, промежуточные результаты, ревью и накопленный опыт. Изменение навыка проходит сравнение и подтверждение перед применением.

Для нового проекта начните с [установки](../../README.md#начать-проект), затем пройдите [пример исследования](../work-system.md#пример-исследование-по-этапам). Для существующего проекта выполните обновление ниже.

## Что изменилось

- Координатор, исследователь, редактор, рецензент и библиотекарь получили контракты с входами, результатами, процедурами и границами ответственности.
- Сценарии `ingest`, `research`, `decision` и `revalidate` сохраняют этапы и проверяемые артефакты в записи задачи. Новая сессия получает следующий шаг и обнаруживает устаревшие результаты.
- Необязательный профиль хранит собственные роли и сценарии проекта. Пакет контекста включает обязательные документы и подходящие принятые уроки; пробелы показываются явно.
- Клиенты и SkillOpt находят стандартные `skills/<имя>/SKILL.md` и прежние плоские навыки одинаково. Предлагаемая версия сравнивается с действующей на одинаковых примерах; неудачная или изменённая после проверки версия не применяется.
- Очередь находок объединяет аудит, дайджест и замечания. Опыт работы хранится отдельно от предметных фактов. Метрики показывают размер выборки, а при отсутствии наблюдений — недостаточность данных.

## Перейти с 0.4.0

Сохраните изменения проекта в Git. Сначала просмотрите обновление:

```bash
pnpm kb:update --ref v0.5.0
pnpm kb:update --ref v0.5.0 --apply
pnpm run setup
pnpm harness:setup
pnpm check
```

Разберите указанные конфликты и проверьте `git diff` перед коммитом. `harness:setup` синхронизирует копии навыков уже выбранных клиентов и сохраняет локальные изменения; для первого подключения укажите `--client codex` или [другой клиент](../compatibility.md). Проекты без исходной базы сначала проходят [принятие известной версии](../upgrades.md#старый-проект-без-lock).

Старые задачи и проекты без профиля сохраняют прежний режим работы. Проектные роли в `00_context/work-system.json`, навыки в `skills/` и записи `.remember/` не перезаписываются обновлением.

Прежнее предложение SkillOpt нельзя сразу применить: подготовьте сравнение и подтвердите проверенную версию по [руководству](../work-system.md). Команды `rollout`, `reflect` и `compare` вызывают модель только с `--execute`. Для накопления результатов аудита используйте `pnpm kb:findings scan` или `pnpm kb:doctor --record-findings`; обычный `kb:doctor` только читает состояние.

Корневой `.gitignore` принадлежит проекту. Добавьте правила `.remember/findings/*.lock` и `.remember/findings/*.tmp`, сохранив сами `.remember/findings/*.json` в Git.

## Проверки

| Область | Подтверждённое поведение |
|---|---|
| Основной набор | 113 автоматических тестов: роли, профили, сценарии, клиенты, обновления, находки и жизненный цикл навыков |
| Передача задачи | Восстановление этапа; отказ при пустом результате, нарушении порядка, отсутствующем ревью или подтверждении решения; обнаружение изменённых артефактов и контрактов |
| SkillOpt | Одинаковые примеры для обеих версий; блокировка регрессии и устаревшей проверки; сохранность локальных изменений при применении и откате |
| Обновление шаблона | Сохранение проектного профиля, собственных навыков и принятых уроков во временных репозиториях |
| Общие проверки | Связи контрактов, пространства, переносимость, читаемость и происхождение выводов |
| Поиск и проверка доказательств | 26 проверок retrieval, control и adversarial gate |
| Витрина | Десять тестов данных и компонентов; статическая сборка |

Повторить проверки исходного шаблона:

```bash
pnpm test
pnpm check
pnpm viewer:test
pnpm viewer:build
node scripts/semantic/test-retrieval.mjs
node scripts/semantic/test-control.mjs
node scripts/semantic/test-gate.mjs
pnpm kb:release:check
```

Внешние модели и живые сеансы клиентов в этом выпуске не проверялись. Тесты используют локальные заглушки. Отдельный контекст ревью и подтверждения записываются в журнал; система не удостоверяет личность автора и не ограничивает инструменты клиента. Формальные проверки не доказывают истинность выводов.

Управление новой рабочей системой доступно через команды и агентов. Отдельная веб-админка, расписания и сервер агентов в этот выпуск не входят.
