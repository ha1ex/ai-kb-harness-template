# Выпуск 0.6.0 — исследования с распределением моделей

9 сентября 2026 года. Исследование получает план, ограниченные задания исполнителям, сохранённые доказательства и отдельную проверку результата. Сильная модель планирует, обобщает и проверяет; более экономичные модели собирают материалы. Конкретные модели выбирает проект.

## Что добавлено

- `kb:research` сохраняет историю между сессиями: план, попытки, ошибки, источники, расходы и замечания ревью. По умолчанию команда готовит запросы для текущего клиента; автоматические вызовы требуют `--execute`.
- Политика задаёт модели по ролям, число исполнителей и параллельных заданий, лимиты повторов и контекста. Необязательные лимиты токенов и стоимости сохраняют резерв на ревью. Неизвестные расходы показываются явно.
- Проверки требуют точных цитат, сохранения неопределённости и обеих сторон противоречия, а также ревью каждого итогового утверждения. Изменённые источники и записи требуют перепроверки. Исчерпание бюджета не означает успешное завершение.
- Навык `economical-research` и [руководство](../research.md) связывают цикл с существующими клиентами, контекстом и передачей задач.

## Обновить существующий проект

Сохраните текущую работу в Git, затем просмотрите и примените обновление:

```bash
pnpm kb:update --ref v0.6.0
pnpm kb:update --ref v0.6.0 --apply
pnpm run setup
pnpm harness:setup
pnpm check
```

Разберите показанные конфликты перед коммитом. Проектные `00_context/work-system.json`, `00_context/research-policy.json`, `skills/` и `.remember/` сохраняются. README существующего проекта также принадлежит проекту: инструкция выпуска переносится в `docs/releases/0.6.0.md`, без замены вашей главной страницы. Без `.harness/lock.json` сначала [примите известную исходную версию](../upgrades.md#старый-проект-без-lock).

Новая политика необязательна. Если её ещё нет, скопируйте образец и задайте конкретные модели:

```bash
cp -n harness/templates/research-policy.json 00_context/research-policy.json
pnpm harness:check
pnpm kb:research init --task research-01 --owner me --question "Какие доказательства нужны для решения?"
pnpm kb:research prepare --task research-01 --owner me --role planner
pnpm kb:research show --task research-01
```

Эти команды не вызывают модель. Для полноценного исследования передайте подготовленные запросы выбранным моделям и сохраняйте ответы по [примеру](../research.md#start-with-the-manual-workflow). Политика фиксируется при создании задачи: настройте её до `init`.

## Проверка выпуска

Пройдено 154 основных теста (из них 41 — для исследования), 26 проверок поиска и доказательств, тесты и сборка витрины, общие проверки проекта. Обновление отдельного проекта с 0.5.0 перенесло 19 изменений без конфликтов и сохранило его настройки, собственный навык, источники и историю; новый навык подключился к Codex, планировщик получил модель проекта без её вызова.

Автоматические проверки покрывают распределение моделей, полный цикл ручной и HTTP-работы, параллельную запись результатов, ограничения вызовов, неизвестный расход, повторную проверку после изменения источника, выдуманные цитаты, обход ограничений путей и сохранение истории при обновлении.

```bash
pnpm test
pnpm check
pnpm kb:verify --scan --provenance --no-semantic
pnpm viewer:test
pnpm viewer:build
pnpm kb:release:check
```

Внешние платные модели не запускались; HTTP-тесты используют локальный сервер. Экономия и качество реальных моделей пока не измерены. Для сравнения используйте одинаковые 10–20 вопросов проекта в смешанном режиме и режиме одной сильной модели, учитывая ошибки, ревью, повторы и полную стоимость инструментов.

Роль задаёт инструкции, а не права доступа. Ручные сведения о модели, контексте и расходе не удостоверяются автоматически. Точное совпадение цитаты не доказывает истинность вывода. Токены оцениваются до вызова и сверяются после ответа; скрытые расходы провайдера или дочерних инструментов не дают гарантии точного ограничения счёта. `maxOutputTokens` передаётся HTTP-провайдеру; для ручных и CLI-вызовов он используется в резерве, а реальные ограничения задаются в клиенте. Нового сервера и веб-экрана управления исследованиями нет.
