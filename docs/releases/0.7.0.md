# Выпуск 0.7.0 — навыки под проект, подпись решений и контур, который не молчит

10 сентября 2026 года. Выпуск переносит в шаблон проверенные практики системы агентов PartyStation (разбор — в `04_synthesis/pstv-agents-adoption.md`): навык создаётся из эталона и виден в реестре вместе с теми, кто его использует; решение считается принятым только с подписью человека; всё, что ждёт человека, собрано в один инбокс; ночной контур и общая проверка больше не молчат о пустых и упавших шагах; архитектурные договорённости проверяются инвариантами с храповиком.

## Что изменилось

- **Навыки.** `pnpm skill new <имя>` создаёт черновик из `harness/templates/skill/` только в `.context/`; дальше штатный `propose → compare → approve → apply`. Необязательные поля `status: draft|verified|deprecated` и `version`; навык со статусом `deprecated` нельзя назначить роли, этапу или профилю, и он не копируется клиентам. `pnpm kb:roster` показывает роли, этапы сценариев, навыки, их потребителей и копии у клиентов; `pnpm skill list` печатает `used-by`; `pnpm harness:check` предупреждает о проектных навыках без потребителя при активном профиле.
- **Петля «практика → урок → навык».** `pnpm kb:findings papercut "<текст>"` записывает трение одной строкой (повторы копятся как наблюдения, это не бэклог); `pnpm kb:findings from-reviews [--record]` превращает замечания рецензента из handoff в открытые находки; `pnpm skill propose --from-findings <id,…>` принимает только уроки, подтверждённые человеком, и вносит их в rationale и хеш предложения; `reflect` видит принятые уроки и обязан ответить строкой `KNOWN-ERRORS-CHECK:`; дайджест показывает повторяющиеся замечания без предложения навыка.
- **Решения.** `pnpm kb:approve --file … --by … --reference …` ставит `status: accepted` и подпись эффекта (`approved_by`, `approved_at`, `approved_ref`, `approved_hash` — SHA-256 канонизированного тела). Хук `check-decisions` блокирует агентскую запись `accepted` без действующей подписи; `verify --scan` краснеет на устаревшей подписи (отсутствие подписи — advisory, гейт при `approval.required: true`); `kb-doctor` показывает такие решения. Словарь статусов: `proposed → accepted | rejected`.
- **Инбокс.** `pnpm kb:inbox` и дайджест собирают всё, что ждёт человека: решения, этапы задач без ревью или подтверждения, сравнения навыков без `approve`, предложение профиля, кандидаты `.context/inbox`, открытые находки, подготовленные запросы `kb:research`. У каждой карточки — место и одна команда. `kb:metrics` считает ожидающие решения и просроченные дольше семи дней.
- **Свежесть знаний.** `stale_synthesis` считается по дате документа (`updated`/`date`/`ingested`), затем по последнему коммиту, затем по mtime; `status: living` не стареет; порог `doctor.staleDays` в `kb.config.mjs` общий для `kb-doctor` и `think`.
- **Тишина не успех.** Шаги ночного контура пишут записи `run` в журнал; дайджест открывается секцией «Ночной контур», печатает Health даже при упавшем doctor, записывает доставку webhook и завершается кодом 1 при недоставке; `--strict` превращает любое предупреждение в exit 1; `verify --scan` предупреждает о нуле проверенных файлов (`--require-files` — гейт); `pnpm check` прогоняет все проверки до конца и печатает сводку (`--fail-fast` — прежнее поведение).
- **Инварианты с храповиком.** `harness/invariants.json` и `pnpm kb:invariants` (входит в `pnpm check`): один резолвер `KB_ROOT`, один парсер frontmatter, имена моделей только в конфиге, тесты без живой сети, длина файла до 900 строк, достижимость скриптов. Существующие нарушения заморожены по путям с датой; новое нарушение — красный; вылеченная заморозка обязана быть удалена. Проектный overlay — `invariants` в `kb.config.mjs`.
- **Справка не отстаёт от кода.** `test/docs-drift.test.mjs` сверяет команды `pnpm`, пути и имена MCP-инструментов в template-owned документации с кодом; таблица «Слои контроля» в `docs/architecture.md` покрывает все гейты pre-push, хуков и CI.
- **Прочее.** Отпечаток контракта этапа учитывает только поля роли, меняющие требования; общий парсер frontmatter нормализует CRLF; сообщение хука `check-decisions` больше не ссылается на несуществующий шаблон.

## Перейти с 0.6.0

Сохраните текущую работу в Git, затем просмотрите и примените обновление:

```bash
pnpm kb:update --ref v0.7.0
pnpm kb:update --ref v0.7.0 --apply
pnpm run setup
pnpm harness:setup
pnpm check
```

Что может измениться после обновления и что с этим делать:

- `kb-doctor` впервые может показать красный `stale_synthesis`: свежесть теперь считается по дате документа. Обновите документ, поставьте `status: living` для живых реестров или поднимите `doctor.staleDays` в `kb.config.mjs`.
- Решения со `status: accepted` без полей `approved_*` показываются как unsigned (advisory). Подтвердите их `pnpm kb:approve` или верните `status: proposed`. Гейт на отсутствие подписи включается `approval.required: true`.
- `pnpm check` получил проверку инвариантов. Если в проекте есть собственные нарушения, заморозьте их по путям через `invariants.frozen` в `kb.config.mjs` или отключите id через `invariants.disabled`.
- `pnpm kb:digest` с заданным `KB_DIGEST_WEBHOOK` завершается кодом 1 при недоставке: cron-лог покраснеет вместо тихого пропуска.
- Завершённые этапы задач, сохранённые до обновления, один раз покажутся устаревшими по контракту (`staleArtifacts`): переоткройте и перепроверьте их.
- Неизвестное значение `status:` во frontmatter навыка теперь ошибка обнаружения; используйте `draft`, `verified`, `deprecated` или удалите поле.

Проектные `00_context/work-system.json`, `00_context/research-policy.json`, `skills/`, `.remember/` и `kb.config.mjs` сохраняются. Новые ключи `approval`, `doctor`, `invariants` необязательны: без них действуют дефолты ядра.

## Проверка выпуска

Пройдено 177 автоматических тестов (25 новых: эталон навыка, статус и версия, отпечаток роли, реестр, дрейф документации, papercut, from-reviews, свежесть, from-findings, подпись решений, инбокс, ночной контур, сводка проверок, инварианты), шесть общих проверок `pnpm check` включая инварианты, 26 офлайн-проверок поиска и доказательств, проверка выпуска. Обновление отдельных проектов с 0.6.0 проверено только тестами обновления на временных репозиториях.

```bash
pnpm test
pnpm check
pnpm kb:verify --scan --provenance --no-semantic
pnpm kb:invariants
pnpm viewer:test
pnpm viewer:build
pnpm kb:release:check
```

Внешние модели и живые сеансы клиентов не запускались. Подпись решения фиксирует, кто и на каком основании согласовал, и защищает от случайной правки; личность она не удостоверяет и от агента, который сам посчитает хеш, не защищает. Заморозки инвариантов описывают текущее состояние оснастки: три резолвера `KB_ROOT`, четыре парсера frontmatter, имена моделей в трёх файлах SkillOpt и один файл длиннее 900 строк чинятся по правилу «извлекай, когда трогаешь». Отложенные практики статьи (замороженная метрика роли, граница автономии как данные, срок годности знаний, команда ревью этапа, личность роли в MCP, уровни серьёзности и инциденты в находках, шаблон роли) перечислены с условиями в `04_synthesis/pstv-agents-adoption.md`.
