# Выпуск 0.8.0 — документы, PDF и методологии

## Главное

Шаблон получил общие улучшения витрины и работы агентов из MPLC по состоянию на 22 октября 2026 года. Существующие поиск, роли, подписи решений и обновление проектов сохраняются.

Каталог связывает основной документ, части и прежние редакции. Читатель скачивает Markdown, открывает печатную версию и PDF. Проверка обнаруживает устаревшие файлы до публикации. Разделы методологий и исследований получают настройки из реестров проекта.

## Что перенесено из MPLC

Канвас показывает схемы с поиском, перемещением, масштабом, связями и источниками. Семь карточек методологий ведут к закреплённым канонам; чужие тексты остаются у первоисточника.

| Основание в MPLC | Общий результат в шаблоне |
|---|---|
| `documents-contract.mjs` и правило каталога | Поля artifact, parent, order, supersededBy; действующая редакция и её архив |
| `home-contract.mjs` и модель навигации | Один основной путь: главный документ, тема исследования, каталог или библиотека |
| MarkdownDownload и печатные записки | Исходник без потерь, общая отрисовка Markdown, A4, PDF и проверка хешей |
| Реестр методологий и карточки линз | Метод выбирается по вопросу; первоисточник, лицензия и редакция видны читателю |
| Реестр исследований | Тема собирает опубликованные результаты, рабочая папка исключается |
| DESIGN_SYSTEM и MPLC Writer | Общие компоненты, состояния, узкий экран и отдельное чтение критиком |
| Инструкции продолжения и готовности | Продолжение с сохранённого шага, фактические проверки и согласованный путь доставки |

Частные модели бизнеса, решения, персональные данные и конкретные разрешения MPLC не становятся содержанием шаблона. Копии чужих канонов не включаются. Полная система графиков, предметные модели карт, оргсхема и специализированные модели MPLC остаются расширениями конкретного проекта.

## Как обновить существующий проект

1. Сохраните изменения проекта в Git.
2. Просмотрите `pnpm kb:update --ref v0.8.0`, затем примените тот же вызов с `--apply`.
3. Выполните `pnpm run setup` и профильные проверки.
4. При необходимости добавьте категории в `kb.config.mjs`, реестры методов и тем по `docs/methods.md`.
5. Добавьте `artifact` к готовым материалам. Для PDF запустите `pnpm kb:document:build <путь.md>`.
6. Выполните `pnpm test`, `pnpm check`, `pnpm viewer:test`, `pnpm viewer:build`.

Новые реестры и примеры не подмешиваются в существующий проект через обновление ядра: они принадлежат проекту. Их отсутствие даёт пустые разделы. Инструкции в AGENTS.md и настройки kb.config.mjs также сохраняются; новые рекомендации внесите осознанно.

Свежая копия шаблона содержит учебный комплект. `kb:init --strip-demo` удаляет только неизменённые примеры. Если пример уже отредактирован, команда сохраняет его и связанные материалы; остатки можно удалить после своей проверки.

## Как проверить глазами

Запустите `pnpm viewer:dev` и откройте адрес из терминала. В свежей копии перейдите в «Документы», найдите учебную записку, откройте приложение и прежнюю версию. В обновлённом проекте выберите свой документ с полем `artifact`. Если таких документов ещё нет, добавьте первый по руководству `docs/documents.md`. Скачайте Markdown и PDF. Откройте «Методологии» и учебную тему в «Исследованиях». Проверьте возврат к фильтрам и узкий экран.

Публикация сайта остаётся отдельной настройкой владельца проекта. Обновление шаблона само по себе не создаёт хостинг и не меняет права доступа.
