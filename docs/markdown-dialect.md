# Поддерживаемая разметка Markdown

## Главное

Пишите стандартный Markdown с GFM. Специальные компоненты нужны, когда они точнее передают сравнение, последовательность или доказательства. Исходный файл должен оставаться понятным без витрины.

## Обычный Markdown

Поддерживаются заголовки, абзацы, ссылки, изображения, списки и чекбоксы, таблицы, цитаты, горизонтальные линии, inline-код и fenced code blocks. Таблицы получают внутреннюю горизонтальную прокрутку. Заголовки второго уровня вида `## 01 · Контекст` отображают номер отдельно.

Локальные ссылки пишутся относительно документа или от корня базы. `node scripts/check-portability.mjs` блокирует `file:///`, `/Users/...` и `/home/...` вне примеров кода.

## Callout и раскрываемое доказательство

Первое жирное слово в цитате задаёт тип: `note`, `tip`, `warning`, `info`, `success` или `danger`.

```markdown
> **warning**
> Данные за апрель ещё не подтверждены.
```

Для подробностей используйте HTML `details`; короткий вывод остаётся видимым. Если у `details` есть `id`, ссылка с таким hash раскрывает блок при открытии документа.

```html
<details id="evidence">
<summary>Доказательства и ограничения</summary>

Проверяемая фактура и ссылки на источники.
</details>
```

## Компоненты витрины

Компоненты ниже уже поддерживаются рендерером. Атрибуты заключайте в кавычки, содержимое пишите Markdown.

```html
<kb-steps>
  <kb-step title="Собрать источники">Зафиксировать период и область.</kb-step>
  <kb-step title="Сверить вывод">Проверить ссылки и ограничения.</kb-step>
</kb-steps>

<kb-accordion>
  <kb-accordion-item id="evidence" title="Дословно">Цитата источника.</kb-accordion-item>
</kb-accordion>

<kb-tabs group="detail-level" defaultLabel="Кратко">
  <kb-tab label="Кратко">Вывод.</kb-tab>
  <kb-tab label="Подробнее">Разбор.</kb-tab>
</kb-tabs>

<kb-tree>
  <kb-folder name="knowledge">
    <kb-file name="overview.md" highlight />
  </kb-folder>
</kb-tree>

<kb-linkcard href="/doc/04_synthesis/overview.md" title="Открыть обзор" desc="Вывод и доказательства" />
```

`kb-steps` показывает последовательность. `kb-accordion` группирует раскрываемые части; `id` элемента работает как глубокая ссылка, а `type="multiple"` разрешает открыть несколько элементов. `kb-tabs` использует `label` вкладки; необязательный `group` сохраняет и синхронизирует выбор, `defaultLabel` задаёт начальную вкладку. `kb-tree` принимает `name`, `open` и `highlight`. `kb-linkcard` создаёт самостоятельный переход по `href` с `title` и необязательным `desc`. Не вкладывайте интерактивные компоненты друг в друга без проверки клавиатурой.

Рендерер пропускает безопасное подмножество сырого HTML. Элементы `script`, `iframe`, `object`, `embed`, `style`, `form` и `input` удаляются. Всё равно считайте документы доверенным содержимым репозитория и проверяйте HTML из внешнего источника перед публикацией.

Метки `[source: /path/to/file.md]` становятся ссылками на документ. Обычные относительные и корневые ссылки на `.md` также открываются внутри витрины.

## Метаданные

Frontmatter — плоский YAML-блок. Минимальные поля задаются для каждого слоя в `kb.config.mjs`; документ без frontmatter допустим, если правила слоя не требуют обратного. Часто полезны `type`, `title`, `date`, `status`, `owner`, `confidence`, `audience`, `related` и `tags`.

```yaml
---
type: synthesis
title: "Вывод по пилоту"
date: 2026-09-06
status: draft
confidence: medium
audience: [product]
related:
  - /02_sources/pilot-notes.md
---
```

`audience` необязателен. Если настроен реестр пространств, `node scripts/check-spaces.mjs` проверяет его значения и ссылки; без реестра команда завершается мягко.
