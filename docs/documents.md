# Документ связывает чтение, исходник и печать

## Главное

Читатель открывает действующую редакцию, видит части комплекта и при необходимости скачивает Markdown или PDF. Настройки проекта определяют категории и доступные слои.

Учебный комплект доступен на `/documents`. Откройте «Учебная записка: как проверить источник», затем приложение и прежнюю версию.

## Каталог собирается из frontmatter

Frontmatter — блок настроек в начале Markdown между строками `---`. По этим полям витрина собирает каталог.

```yaml
---
type: document
version: v0.1
title: "Мой отчёт"
artifact: /06_outputs/documents/my-report.md
category: reports
---
```

В примере файл сохранён как `06_outputs/documents/my-report.md`.

Добавьте к опубликованному Markdown поле `artifact` с путём к Markdown или HTML внутри индексируемого слоя. Markdown открывается на `/doc/<путь>`, HTML — на `/documents/<имя-файла>` в изолированном фрейме. Имя артефакта состоит из латинских букв в нижнем регистре, цифр и дефисов; оно уникально во всей базе.

| Поле | Назначение |
|---|---|
| `artifact` | Явно опубликованный Markdown или HTML |
| `category` | Категория из `viewer.documents.categories`; без поля — `other` |
| `parent` | Путь к Markdown главного документа; только один уровень |
| `order` | Целое положительное место части среди соседей |
| `status: archived` | Прежняя редакция; у неё нет `artifact` |
| `supersededBy` | Путь к действующему документу; цепочки архивов запрещены |
| `print` | HTML печатной версии, который создаёт сборщик |
| `pdf` | Готовый PDF; появляется после успешной сборки |

Архив ищется вместе с действующим документом и открывается из блока «Прежние версии». Его страница ведёт в действующую редакцию. Ссылки на PDF текущей версии в архиве скрыты.

Каталог сохраняет запрос и категорию в URL. При возврате из документа браузер восстанавливает фильтры. Верхняя ссылка страницы ведёт к главному документу, теме исследования или каталогу; библиотека остаётся запасным входом.

## Исходный Markdown скачивается без потерь

Кнопка «Скачать Markdown» сохраняет опубликованный исходник с frontmatter. Она использует тот же текст, который доступен при чтении. Кнопка «Печать / сохранить PDF» открывает системную печать браузера. Кнопка «Скачать PDF» сохраняет заранее собранный файл; она появляется после успешной сборки. Во время печати вкладки и раскрываемые блоки показываются целиком.

## Собранный PDF проверяется перед публикацией

```bash
pnpm kb:document:build 06_outputs/documents/demo-note.md
pnpm kb:documents
```

Сборщик создаёт рядом с Markdown три файла: `<имя>-print.html`, `<имя>.pdf`, `<имя>.export.json`. Последний хранит хеши исходника, печатной версии, PDF и используемого оформления. Сборщик дописывает `print` и `pdf` в исходник.

Для PDF нужен headless Chromium. Установите его командой `pnpm -C tools/viewer exec playwright install chromium --only-shell` или укажите бинарный файл через `KB_CHROME`. Полный Chrome и профиль пользователя не используются. Без Chromium команда сохраняет HTML и выходит с кодом 2; PDF не считается готовым. Флаг `--no-pdf` создаёт только HTML и завершается успешно.

Проверка `pnpm kb:documents` отклоняет изменённый исходник, устаревшее оформление, отсутствующий файл или неверную ссылку. Пересоберите экспорт после редактирования. HTML, PDF и паспорт коммитятся вместе с Markdown. Число страниц не ограничено; текст и вёрстку PDF автор проверяет глазами.

Печатная версия использует тот же Markdown-компонент, что и страница базы. Таблицы, сноски, списки и все вкладки сохраняются. Блоки кода печатаются исходным текстом. Локальные изображения и дополнительные файлы не копируются автоматически: автономность такого документа проверяет автор.

## Публикуются явно выбранные файлы

Статическая сборка копирует только HTML и PDF, названные в frontmatter действующих опубликованных документов. Они доступны под `/published/<путь>`. Символические ссылки, скрытые папки, выход за корень, исключённые папки и непубликуемые слои отклоняются. Исходный `01_raw` по умолчанию закрыт для витрины.

`viewer.excludePaths` исключает рабочие папки. Поле `workdir` темы исследования имеет тот же эффект. Статическая сборка и dev-сервер используют один каталог. Эти настройки определяют состав публикации; доступ к уже собранному сайту настраивается на хостинге.

HTML открывается в iframe без `allow-same-origin`. Адаптер сохраняет внутренние якоря и раскрывает их родительские блоки. Для самостоятельной выдачи HTML хостинг должен добавлять политику `Content-Security-Policy: sandbox allow-scripts allow-popups allow-popups-to-escape-sandbox` к `/published/*.html`; dev-сервер уже делает это. Сборка не создаёт разрешений пользователей и не настраивает авторизацию хостинга.
