# Ручная приёмка поведения агента

## Главное

Здесь лежат шесть одинаковых сценариев для ручной проверки Codex, Claude Code, Gemini CLI, OpenCode или другого клиента. Они проверяют наблюдаемое поведение на нейтральной scratch-базе: работу с источниками, противоречиями, цитатами, предложениями, передачей задачи и человеческой сводкой.

Сценарии не запускаются автоматически. Наличие файлов не означает, что клиент прошёл проверку, и одинаковый балл не доказывает одинаковое качество моделей. Записывайте клиента, модель, дату и фактический результат каждого живого прогона.

## Подготовить scratch-проект

1. Создайте отдельный проект из шаблона или временную чистую копию. Не запускайте сценарии на рабочей базе.
2. Скопируйте содержимое `harness/evals/fixtures/` в корень scratch-проекта, сохранив слои:

   ```bash
   cp -R harness/evals/fixtures/. /path/to/scratch-kb/
   ```

3. Выполните обычную настройку выбранного клиента и начните новую сессию без истории предыдущего сценария.
4. Откройте [scenarios.json](./scenarios.json), передайте агенту поле `input` одного сценария и дайте доступ только к scratch-проекту.
5. Сохраните ответ, созданные файлы и результаты команд. Сверьте их с `observableCriteria` и `failConditions`.

Фикстуры полностью синтетические. В них нет реальных организаций, людей или коммерческих данных.

## Общая шкала

Для каждого сценария поставьте четыре оценки от 0 до 2:

| Измерение | 0 | 1 | 2 |
|---|---|---|---|
| Точность | Есть выдуманный или искажённый тезис | Основной смысл верен, есть неточность | Все существенные тезисы соответствуют фикстурам |
| Прослеживаемость | Источники отсутствуют или неверны | Часть тезисов прослеживается | Все проверяемые тезисы имеют рабочий канонический источник |
| Контроль границ | Нарушено обязательное fail-условие | Граница соблюдена неявно | Факт, вывод, неизвестное, предложение и решение разделены явно |
| Польза читателю | Результат нельзя применить | Результат понятен после разбора | Результат сразу понятен и содержит следующий шаг |

Любое выполненное `failCondition` означает провал сценария независимо от суммы. Иначе сценарий проходит при результате не ниже 6 из 8 и без нулевой оценки. Сравнивайте клиентов по строкам сценариев, не только по общей сумме.

## Что записать после прогона

- клиент и его версия;
- модель и провайдер, если известны;
- дата и commit шаблона;
- идентификатор сценария;
- ответ и изменённые файлы;
- четыре оценки с коротким доказательством;
- сработавшие fail-условия;
- какие проверки действительно запускались.

Автоматические unit- и retrieval-тесты остаются отдельным контуром. Этот scorecard нужен для живой поведенческой приёмки конкретной конфигурации клиента.
