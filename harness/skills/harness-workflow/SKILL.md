# Работа по этапам

Читайте [правила работы](../../../harness/rules/workflow.md) и [пример исследования](../../../docs/work-system.md#пример-исследование-по-этапам).

1. Уточните цель и критерии готовности. Получите `pnpm kb:context --task <id> --workflow <workflow> --json`.
2. Прочитайте выбранную роль, навыки и документы. Разберите `work.missing`, `work.deferred` и `work.staleArtifacts`; `work.ready` означает готовность пакета, а не завершение задачи.
3. Выполните текущий этап. Сохраните результат и именованные непустые файлы через `pnpm kb:session save --task <id> --owner <writer> --file <handoff.json>`. Затем снова получите контекст.
4. Для независимого ревью передайте результат, доказательства и критерии в отдельный контекст. Самопроверка автора не заменяет это ревью. Подтверждение решения фиксируйте только после реального согласования.
5. Если завершённый файл изменился, верните его этап и все последующие в `pending`, сохраните состояние и пройдите их заново. Не переносите старое ревью на изменённый результат.
6. Завершайте задачу после всех этапов и фактических проверок. Иначе сохраняйте открытые вопросы и следующий шаг.

Один агент может выполнять роли последовательно. Эта процедура не запускает агентов и не требует конкретного клиента.
