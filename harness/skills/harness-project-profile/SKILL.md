# Профиль проекта

Читайте [руководство рабочей системы](../../../docs/work-system.md) и [правила работы](../../../harness/rules/workflow.md).

1. Изучите цель проекта, материалы `00_context/`, открытые вопросы и повторяющиеся задачи. Предложите только нужные роли, сценарии и уже доступные навыки.
2. Подготовьте JSON со статусом `draft`; используйте контракты из `harness/roles/` и `harness/workflows/`. Для собственных контрактов выбирайте отдельные ID. Профиль необязателен.
3. Выполните `pnpm kb:profile propose --file <profile.json>` и `pnpm kb:profile show --json`. Покажите человеку конкретное предложение и основания выбора.
4. После подтверждения этого предложения выполните `pnpm kb:profile apply --by <human> --note <authorization-reference>`. Учитывайте уже данное подтверждение, если оно охватывает точное предложение.
5. Проверьте `pnpm harness:check` и `pnpm kb:context --task <id> --workflow <workflow> --json`; сохраните фактический результат в передаче задачи.

Команды не вызывают модель. Поля подтверждения сохраняют запись согласования; они не проверяют личность. Не выдавайте черновик за активный профиль и не превращайте выбранные роли в разрешения на действия.
