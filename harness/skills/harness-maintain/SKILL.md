# Поддержка знаний и процедур

Читайте [руководство рабочей системы](../../../docs/work-system.md#замечания-и-опыт) и [правила доказательств](../../../harness/rules/evidence.md).

1. Получите `pnpm kb:doctor` и `pnpm kb:findings list --json`. Doctor по умолчанию только читает; `pnpm kb:findings scan --json` явно сохраняет наблюдения.
2. Проверьте основания замечания. `knowledge` относится к предметным знаниям; `feedback` — к опыту работы. Добавляйте находки через `pnpm kb:findings add --file <finding.json>` с источником, наблюдением и предлагаемым действием.
3. Согласуйте полезный урок с человеком и запишите `pnpm kb:findings transition --id <id> --status accepted --by <human> --note <confirmation>`. Только принятый `feedback` попадает в уроки контекста. Исправленный материал проверьте перед статусом `resolved`.
4. Перепроверяйте изменённые основания через сценарий `revalidate`. Сохраняйте исходные доказательства и различия между источниками.
5. Изменение проектного навыка проводите через `pnpm skill propose`, `compare`, `approve`, `apply` по [руководству навыков](../../../skills/README.md). Сравнивайте текущий и предложенный варианты на одних случаях; принятие урока само не меняет процедуру. После применения или отката выполните `pnpm harness:setup` и `pnpm harness:check`, чтобы выбранные клиенты получили текущую процедуру.

Подготовленный `kb:dream` запрос не означает выполненный аудит. Модель вызывается только при явном `--execute` и настроенном провайдере. Сообщайте фактические проверки и оставшиеся ограничения.
