# AI KB Harness Template · 0.5.0

**Основа проекта, в котором люди и AI-агенты работают с общей базой знаний.** Собирайте источники, сохраняйте выводы и решения, продолжайте работу в другом агенте и показывайте результаты коллегам через веб-витрину.

Шаблон подходит для исследований, продуктовой работы, консалтинга и внутренней документации. Данные остаются обычными Markdown-файлами в Git. Поиск и проверки работают локально; для генерации текста вы выбираете агента или провайдера модели.

## Последнее обновление — 0.5.0

**9 сентября 2026 · Роли, рабочие сценарии и накопление опыта.** Шаблон связывает отдельные навыки в порядок работы: агент получает роль и контекст, сохраняет результат каждого этапа и передаёт следующий шаг новой сессии.

- **Пять ролей и четыре сценария:** новый источник, исследование, подготовка решения и перепроверка знания. Профиль подбирается под задачи проекта; собственные роли и навыки сохраняются при обновлении шаблона.
- **Проверяемая передача работы:** пустой результат или отсутствующее обязательное ревью не позволяют завершить этап. Изменённый артефакт требует перепроверки; решение требует подтверждения владельцем.
- **Улучшение на основе опыта:** библиотекарь собирает находки аудита и замечания. SkillOpt сравнивает версии навыка на одинаковых примерах и применяет успешно проверенную версию после подтверждения.

После установки попробуйте:

```bash
pnpm kb:context --task research-01 --workflow research --json
```

Команда покажет первый этап, роль, нужные процедуры и пробелы контекста. Она не запускает исследование или модель. [Пошаговый пример](docs/work-system.md#пример-исследование-по-этапам) · [Проверки и переход на 0.5.0](docs/releases/0.5.0.md) · [История изменений](CHANGELOG.md).

## Что вы получаете

- **Понятную витрину:** разделы по темам, краткая суть, поиск документов, оглавление и раскрываемые источники.
- **Общие правила агентов:** факты отделены от предположений, выводы имеют источники, незавершённая работа передаётся следующей сессии.
- **Работу по ролям и этапам:** контекст под задачу, сохранённые промежуточные результаты, проверка и накопление подтверждённого опыта.
- **Локальный поиск:** смысл, точные термины, связи между документами и даты.
- **Проверки качества:** ссылки, метаданные, происхождение выводов, настройка клиентов и воспроизводимые тесты.
- **Обновляемую оснастку:** новые выпуски шаблона можно переносить в проекты с сохранением их контента и настроек.

```mermaid
flowchart LR
    S[Источники] --> K[База знаний в Git]
    K --> A[Агенты: поиск и работа с контекстом]
    A --> V[Проверка источников и результата]
    V --> K
    K --> W[Веб-витрина для людей]
    P[Настройки проекта] --> A
    P --> W
```

## Начать проект

Нужны **Node.js 22**, **pnpm 9** и Git. В репозитории есть `.nvmrc`; `corepack enable` включает pnpm.

1. Нажмите **Use this template → Create a new repository** на GitHub и клонируйте созданный проект.
2. В каталоге проекта выполните:

```bash
pnpm run setup
pnpm kb:init --name "Исследование продукта" --purpose "Собрать доказательства и выбрать следующий шаг" --strip-demo --yes
pnpm harness:setup --client codex
```

3. Добавьте исходный документ в `01_raw/`, а его краткое саммари — в `02_sources/`. Пример структуры есть в [examples/human-kb](examples/human-kb/README.md).
4. Постройте индекс и проверьте базу:

```bash
pnpm kb:index
pnpm kb:search "главный вопрос исследования"
pnpm kb:doctor
pnpm check
```

5. Откройте витрину:

```bash
pnpm viewer:dev
```

Адрес: [localhost:5173](http://localhost:5173). Новому проекту можно задать название, описание и разделы без изменения компонентов.

Первое индексирование скачивает модель эмбеддингов; затем поиск работает локально. Генерация текста через настроенный внешний провайдер отправляет ему выбранный контекст. По умолчанию автоматические LLM-вызовы выключены.

`--strip-demo` удаляет только известные неизменённые демонстрационные файлы. Дописанные вами материалы сохраняются. Изолированные примеры в `examples/` не попадают в основной поисковый индекс. После инициализации сохраните `.harness/lock.json` в Git вместе с проектом.

## Подключить агента

Правила хранятся в одном каноне: [AGENTS.md](AGENTS.md) → [harness/rules](harness/rules/). Процедуры оформлены как переносимые `SKILL.md`. У каждого клиента свой способ загрузки этого канона.

| Среда | Подключение | Что учитывать |
|---|---|---|
| Codex с GPT | `pnpm harness:setup --client codex` | Общий AGENTS, навыки и пример MCP-конфигурации |
| Claude Code | `pnpm harness:setup --client claude` | CLAUDE.md импортирует AGENTS; доступны MCP и хуки |
| OpenCode, в том числе с GLM | `pnpm harness:setup --client opencode` | Модель выбирается в клиенте |
| Gemini CLI | `pnpm harness:setup --client gemini` | Собственный файл входа и MCP-адаптер |
| Другой MCP-клиент | `pnpm harness:setup --client mcp` | Явно загрузите правила и подключите сервер |

Можно выбрать несколько клиентов. Сохраните `.harness/clients.json` и созданные файлы клиента в Git вместе с проектом. Setup сохраняет чужие настройки и сообщает о конфликтующих изменениях. Git hooks включаются отдельно флагом `--hooks`. Проверка без исправлений: `pnpm harness:check`.

**Проверенная конфигурация не равна проверенному живому сеансу модели.** В [матрице совместимости](docs/compatibility.md) отмечено, какие проверки выполнены. Общие правила и инструменты доступны разным клиентам; качество ответов зависит и от модели.

MCP-сервер предоставляет `kb_search`, `kb_think`, `kb_backlinks`, `kb_verify`, `kb_retain`, `kb_promote`. Подробности — [semantic/README](scripts/semantic/README.md). Протокол и CLI доступны независимо от веб-витрины.

## Витрина для людей

Главная отвечает на вопросы «что это за проект» и «с чего начать». Разделы объединяют документы по теме, библиотека сохраняет доступ ко всему выбранному корпусу. Документ показывает статус, дату, владельца, содержание и связанные источники.

![Главная веб-витрины: разделы, стартовые документы и последние изменения](docs/assets/viewer-light.png)

Порядок чтения: **суть → объяснение → доказательства**. Правила и примеры: [человеческий интерфейс](docs/human-interface.md), [разметка документов](docs/markdown-dialect.md).

Настройка проекта:

| Файл | Что менять |
|---|---|
| `00_context/project.json` | Название, описание, статус и уровень подключения; создаётся `kb:init` |
| `00_context/work-system.json` | Необязательный профиль ролей, сценариев и процедур; создаётся `kb:profile` после подтверждения |
| `00_context/spaces.json` | Темы и стартовые документы |
| `kb.config.mjs` | Слои, правила проверки, параметры LLM и явные настройки витрины |
| `.remember/core.md` | Устойчивый контекст проекта |
| `.remember/preferences.md` | Предпочтения формы ответа |
| `skills/` | Ваши дополнительные навыки |

`audience: [research]` относит документ к разделу `research`. Без этого поля документ остаётся в библиотеке и поиске. Аудитория задаёт навигацию, а не ограничение доступа.

```bash
pnpm viewer:test
pnpm viewer:build
```

Сборка создаёт `tools/viewer/dist/` для статического хостинга. Настройки экспорта, поиска и прямых URL описаны в [руководстве витрины](tools/viewer/README.md). Публикуйте только материалы, предназначенные выбранной аудитории; отдельного сервера авторизации в шаблоне нет.

## Как организовано знание

| Слой | Назначение |
|---|---|
| `00_context` | Цель, словарь, участники и правила проекта |
| `01_raw` | Исходные материалы; новая редакция сохраняется отдельно |
| `02_sources` | Саммари отдельных источников |
| `03_wiki` | Понятия и связи между источниками |
| `04_synthesis` | Выводы, гипотезы, противоречия и открытые вопросы |
| `05_decisions` | Решения, действительно утверждённые владельцем |
| `06_outputs` | Материалы для людей; внешние справочные библиотеки отмечены отдельно |

Агент различает `FACT`, `INFERENCE`, `ASSUMPTION`, `UNKNOWN`, `RISK`, `DECISION`, `RECOMMENDATION`. Значимый факт получает ссылку, например `[source: /02_sources/interview.md]`. Формальная проверка ссылки подтверждает наличие и допустимость источника; оценка смысла и истинности требует чтения самого материала.

Исходный документ → саммари → обновление wiki/синтеза → открытые вопросы → индекс и журнал. Решение, упомянутое в источнике, ещё не означает утверждение владельцем проекта. Полный порядок — [правила evidence](harness/rules/evidence.md).

## Продолжать работу в другой сессии

```bash
pnpm kb:context --task research-01
pnpm kb:session --help
```

У задачи свой файл состояния и владелец записи. Передача включает цель, критерии завершения, решения, источники, изменения, проверки и следующий шаг. Формат и команды — [совместимость и работа с сессиями](docs/compatibility.md), [шаблон передачи](harness/templates/handoff.json).

Устойчивое знание хранится в базе; временные заметки — в `.context/`. `kb_retain` сохраняет заметку на разбор, `kb_promote` добавляет карточку ответа после проверок. Эти проверки не заменяют подтверждение решения человеком.

## Роли, сценарии и опыт проекта

Агент может продолжать задачу по готовому сценарию с проверяемыми промежуточными результатами:

```bash
pnpm kb:context --task research-01 --workflow research --json
pnpm kb:profile show --json
pnpm kb:findings list --json
```

Доступны сценарии `ingest`, `research`, `decision`, `revalidate` и пять ролей: координатор, исследователь, редактор, рецензент и библиотекарь. Пакет контекста показывает следующий этап, процедуры, источники, принятые уроки и недостающие материалы. Сохранение этапа проверяет наличие результатов; изменение проверенного файла требует перепроверки.

Профиль создаётся под задачи проекта и включается после подтверждения. Повторяющиеся замечания сохраняются отдельно от предметных фактов. SkillOpt сравнивает действующий и предлагаемый скиллы на одинаковых примерах; применение требует успешной проверки и подтверждения именно этой версии. Автоматических вызовов модели для новых команд нет: выполнение оценки включается `--execute`.

[Пошаговое руководство: настройка, передача задачи, обратная связь и улучшение скилла](docs/work-system.md). Старые задачи без сценария продолжают работать.

## Выбрать уровень подключения

| Уровень | Возможности |
|---|---|
| L0 | Локальный поиск по существующим Markdown-материалам |
| L1 | Поиск, MCP и общие правила работы |
| L2 | Дополнительно формальные проверки и CI |
| L3 | Дополнительно аудит, исправление ответов и SkillOpt |

`kb:init --level 0..3` сохраняет выбранный уровень. На L0/L1 инициализация отключает только неизменённые шаблонные CI-гейты и хуки проверки в неизменённом шаблонном файле настроек. Свои workflow и настройки сохраняются. Для минимальной установки достаточно `pnpm -C scripts/semantic install`; витрина и SkillOpt устанавливаются по потребности. Полный `pnpm run setup` ставит все три части.

`kb:think`, `kb:critic` и `kb:dream` готовят запросы для агента. Флаг `--execute` использует явно настроенный `llm` в `kb.config.mjs`; ручной режим возвращает запрос без обращения к модели. Поддерживаются Claude CLI, общий CLI, OpenAI-совместимый HTTP и локальный Ollama через адаптеры. Подробнее — [совместимость](docs/compatibility.md).

## Обновлять уже созданные проекты

Новый выпуск обновляет оснастку отдельно от материалов проекта. Общая история Git с шаблоном не нужна.

```bash
pnpm kb:update --ref v0.5.0          # посмотреть изменения
pnpm kb:update --ref v0.5.0 --apply  # применить безопасные изменения
pnpm run setup
pnpm harness:setup                 # обновить копии навыков выбранных клиентов
pnpm check
```

Без `--ref` выбирается последний опубликованный числовой тег. Перед применением рабочая копия должна быть чистой. Инструмент показывает конфликты и сохраняет локально изменённые файлы. После применения прочитайте `git diff`, выполните проверки и закоммитьте результат. Конфликты возвращают код 2; успешно обновлённые пути не теряются при повторном запуске.

Граница обновления — [.template-manifest.json](.template-manifest.json), исходная база проекта — `.harness/lock.json`. Собственные данные, правила проекта и настройки защищены; в `package.json` управляются отдельные поля.

Для проектов старого шаблона сначала нужно явно принять известную базовую версию. Пошагово: [обновление и миграция](docs/upgrades.md).

```bash
pnpm test

pnpm viewer:test
pnpm viewer:build
pnpm kb:release:baseline

```

Генерация baseline — команда автора шаблона перед выпуском, не способ принять локальные изменения проекта за новую базу. В CI дополнительно работают тесты retrieval, проверки цитат и эталонные поисковые запросы.
